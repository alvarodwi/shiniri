# Solo Raid Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/solo-raid` page that appends one finished `SoloRaid` row per save.

**Architecture:** Pure row logic in `src/services/soloRaid/`, a `raidStore` that reads columns A and C
and writes through `writeTabsAtEnd`, and a page. No writer changes.

**Tech Stack:** Vue 3, Pinia, UnoCSS, Vitest, Sheets REST API v4.

**Spec:** `docs/superpowers/specs/2026-11-19-solo-raid-design.md`

## Global Constraints

- Append-only, through `writeTabsAtEnd` only.
- `SoloRaid` headers, exact: `season | month | boss | weakness | totalDmg | rank | comments`.
- Weaknesses, exact: `Fire`, `Water`, `Wind`, `Electric`, `Iron`.
- Rank text: `'{x.toFixed(2)}%` (0 < x ≤ 100) or `'#{n}` (integer 1-500).
- AuditLog form name: `SoloRaid`. Nav label: `Solo Raid` (a Union Raid page comes later).
- No commits until the owner says "commit and merge".
- Checks: `yarn format && yarn lint && yarn check && yarn build && yarn test`.

## Review Focus

- Season already logged (double save, another device): refused at save time, nothing written.
  Test in Task 2.
- Damage typed with separators (`12,345,678,901`, `12.345.678.901`, `12 345`) parses; empty, `0` or
  letters is invalid. Test in Task 1.
- Rank switched between modes with a value typed: the value is re-validated in the new mode (8.5 is
  fine as %, invalid as #). Test in Task 1.
- A boss name with a leading `=` or `+` stays text. Test in Task 1.
- Last column-A cell isn't a number (hand edit): season starts blank and the page still loads.
  Test in Task 1.

### Task 1: Config, types and row logic

**Files:**

- Modify: `src/config/sheets.ts` (`SOLO_RAID_TAB`)
- Create: `src/types/soloRaid.ts`, `src/services/soloRaid/soloRaidRows.ts`, `src/services/soloRaid/soloRaidRows.test.ts`

**Interfaces (produces):**

- `WEAKNESSES` (const tuple above), `type Weakness`, `type RankMode = 'percent' | 'place'`,
  `type RaidEntry = { season: number | null; date: string; boss: string; weakness: Weakness | null;
damage: string; rankMode: RankMode; rank: string; comments: string }` in `src/types/soloRaid.ts`.
- `nextSeason(colA: string[]): number | null`: last filled value below the header + 1; `1` for
  header-only; `null` when that value isn't a number.
- `pastBosses(colC: string[]): string[]`: distinct trimmed non-empty values below the header,
  most recent first.
- `parseDamage(s: string): number | null`: strip `,` `.` `_` and whitespace; a positive safe
  integer or null.
- `rankText(mode: RankMode, s: string): string | null`: `'7.95%` / `'#123` or null when invalid.
- `toRow(e: RaidEntry): Cell[] | null`: `[season, date, asText(boss.trim()), weakness,
damage, rank, asText(comments.trim())]`, or null when any required part is invalid (season not a
  positive integer, empty date or boss, no weakness, bad damage or rank).

- [ ] **Step 1: Failing tests:**
  - `nextSeason(['season','1','2'])` → 3; `nextSeason(['season'])` → 1;
    `nextSeason(['season','2','',' '])` → 3; `nextSeason(['season','2','x'])` → null.
  - `pastBosses(['boss','A','B','A',' ',''])` → `['A','B']`.
  - `parseDamage` gives `12345678901` for `'12,345,678,901'`, `'12.345.678.901'` and
    `' 12 345 678 901 '`; null for `''`, `'0'` and `'12a'`.
  - `rankText('percent','7.95')` → `"'7.95%"`; `'7.9'` → `"'7.90%"`; `'100'` → `"'100.00%"`;
    `'0'`, `'100.01'`, `''` and `'abc'` → null. `rankText('place','123')` → `"'#123"`; `'8.5'`,
    `'0'` and `'501'` → null.
  - `toRow` of a full entry → `[45, '2026-11-14', "'Mother Whale", 'Electric', 12345678901,
"'7.95%", '']`. A boss `'=1+1'` → `"'=1+1"`. Missing weakness → null. Season 0 → null.
- [ ] **Step 2:** `yarn vitest run src/services/soloRaid` → FAIL.
- [ ] **Step 3:** Implement.

### Task 2: Raid store

- Produces: `useSoloRaidStore`. State: `entry: RaidEntry` (date `gameDay()`, rankMode `'percent'`),
