# Monorepo Merge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `alvarodwi/shiniri` into a monorepo with the web app in `ui/`, the CLI with full
history in `cli/`, one root `docs/superpowers/`, and a root `CLAUDE.md` that holds the sheet
contract and development flow.

**Architecture:** There are three commits on `feat/monorepo` in `~/files/git/shiniri`:
1. `git mv` the web app into `ui/`.
2. Merge a `git filter-repo`-rewritten copy of `shiniri-cli` (`develop`) into `cli/` with
   unrelated histories.
3. Move docs to the root and write the root, `ui/` and `cli/` context files.

Behaviour of the app and the CLI doesn't change. Each part's existing checks are the proof.

**Tech Stack:** git, `uvx git-filter-repo`, yarn 4 (Vue/Vite), uv (Python 3.14), Netlify.

**Spec:** `docs/superpowers/specs/2026-11-21-monorepo-design.md`

## Global Constraints

- The owner approved exactly three commits on `feat/monorepo`, for this branch only. Make no
  other commits and don't push.
- Don't rewrite old specs or plans. Paths inside them stay as written.
- No app or CLI behaviour change and no sheet change.
- Prettier covers `ui/` only. Root Markdown isn't formatted.
- Each section of the context files lives in one place only. Neither `ui/CLAUDE.md` nor
  `cli/CLAUDE.md` repeats the sheet contract or the development flow.
- The local `~/files/git/shiniri-cli` folder isn't deleted or changed. It is only cloned from.

## Review Focus

1. **Files lost or changed in the CLI import.** Expect `HEAD:cli` to have the same tree hash as
   `shiniri-cli` `develop` (Task 2, Step 5).
2. **Untracked local files stranded at the root** (`.env.local`, CLI `config/` and `data/`).
   Expect them under `ui/` and `cli/`, and expect `git status --short --ignored` at the root to
   show only `.codegraph/` and `.superpowers/` there (Task 3, Step 9).
3. **CLI data paths after the move.** Expect `uv run shiniri-cli` in `cli/` to find the copied
   `data/` (Task 2, Step 7).
4. **Netlify can't find yarn 4 or the build under `ui/`.** Expect `yarn build` from `ui/` to
   write `ui/dist/` (Task 1, Step 5). The real deploy is the owner's check.
5. **Stale cross-repo pointers in the new context files** (`../shiniri`, "web app next door",
   `shiniri-cli` as a separate repo). Expect the grep in Task 3, Step 8 to find nothing.

### Task 2: Import shiniri-cli history into `cli/` (commit 2)

**Files:**
- Create (via merge): `cli/` holding the whole `shiniri-cli` `develop` tree, including
  `cli/docs/` until Task 3.
- Copy (untracked, local): `~/files/git/shiniri-cli/config/{cookie.txt,service-account.json,sheets.json}`
  and `~/files/git/shiniri-cli/data/` into `cli/`.

**Interfaces:**
- Consumes: Task 1's root, which holds only `ui/` and `docs/`.
- Produces: `cli/` with history, where `git log -- cli/src/shiniri_cli/sheets.py` shows commits
  older than the merge.

- [ ] **Step 1: Clone fresh into the scratchpad**

  ```bash
  S=/tmp/claude-1000/-home-varoa-files-git-shiniri-cli/21e0ae15-7ca5-4cb5-a256-4484223c2f39/scratchpad/cli-import
  git clone --no-local --single-branch --branch develop ~/files/git/shiniri-cli "$S"
  ```

- [ ] **Step 2: Rewrite the paths**

  Run `cd "$S" && uvx git-filter-repo --to-subdirectory-filter cli`.
  Expected: `git -C "$S" ls-files | grep -v '^cli/'` prints nothing.

- [ ] **Step 3: Merge**

  ```bash
  cd ~/files/git/shiniri
  git fetch "$S" develop
  git merge --allow-unrelated-histories --no-edit FETCH_HEAD -m "chore: import shiniri-cli history into cli/"
  ```

  Expected: no conflicts, because the root has only `ui/` and `docs/`, and the import has only
  `cli/`.

- [ ] **Step 4: Check history survived**

  Run `git log --oneline -- cli/src/shiniri_cli/sheets.py`.
  Expected: more than one commit, all older than the merge.

- [ ] **Step 5: Check the tree matches exactly**

  Run `[ "$(git rev-parse HEAD:cli)" = "$(git -C ~/files/git/shiniri-cli rev-parse 'develop^{tree}')" ] && echo same`.
  Expected: `same`.

- [ ] **Step 6: Copy local config and data**

  Run `cp -a` on the three config files and `data/` from `~/files/git/shiniri-cli/` into `cli/`.
  This copies and never moves. Then `chmod 600 cli/config/service-account.json`.

- [ ] **Step 7: Run the CLI checks**

  Run `cd cli && uv sync && uv run pytest`.
  Expected: all pass.

  Then run `printf 'q\n' | uv run shiniri-cli`.
  Expected: the status line shows the same stored-data counts as the same command in
  `~/files/git/shiniri-cli`.

  No commit step: the merge in Step 3 made commit 2.

### After the branch (not commits; in this order)

1. A fresh reviewer reads the whole branch: the diffs of commits 1 and 3, plus Task 2, Steps 4
   and 5 as proof for commit 2. Fix all of its findings, and amend them into commit 3 with the
   owner's OK.
2. Owner pre-merge checks: `cd ui && yarn dev` signs in against the sheet copy, and
   `cd cli && uv run shiniri-cli watch` writes nothing new (today is already written) and exits
   cleanly on Ctrl+C.
3. Owner says "merge". Fast-forward `develop` to `feat/monorepo`, then delete the branch.
4. Owner steps from the spec:
   - Clear the build fields in the Netlify UI.
   - Push.
   - Release `0.3.2` per `CONTRIBUTING.md`.
   - Do the homeserver switch (spec step 7).
   - Re-index CodeGraph at the root.
   - Archive `shiniri-cli` with a README pointer.
