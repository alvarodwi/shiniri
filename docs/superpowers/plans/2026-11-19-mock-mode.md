# Mock Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `yarn dev:mock` runs the app signed in, on an in-memory fake sheet, for UI review.

**Architecture:** An in-memory `SheetsApi` in `src/services/mock/`, installed into the
`authStore` forwarding `sheetsApi` by `main.ts` only when dev-only `MOCK` is on.

**Tech Stack:** Vue 3, Pinia, Vite modes, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-19-mock-mode-design.md`

## Global Constraints

- `__MOCK__` (vite `define`: `command === 'serve' && mode === 'mock'`). Mock code is imported only
  inside a `__MOCK__` branch. (Changed during the build: an env-based `MOCK` export left the mock
  chunks in `dist/`.)
- Fixture headers come from `src/config/sheets.ts`, never retyped.
- Banner copy, exact: `Mock data: nothing is sent to Google.`
- No commits until the owner says "commit and merge".
- Checks: `yarn format && yarn lint && yarn check && yarn build && yarn test`.

## Review Focus

- The production build contains no mock code. Check `dist/` for the fixture strings in Task 2.
- A range on a tab the fake doesn't know returns `[]` for reads and throws for writes, so a
  forgotten fixture fails loudly on save. Test in Task 1.
- Reading `'Tab'!A:A` after a write that leaves gaps keeps the inner blanks (`nextEmptyRow`
  depends on them). Test in Task 1.
- A write's leading `'` is stripped and numbers keep their value. Test in Task 1.
- Running `yarn dev` (no mode) behaves exactly as before: Google sign-in, real API.

### Task 1: Fake sheet

**Files:** Create `src/services/mock/mockSheetsApi.ts`, `src/services/mock/mockSheetsApi.test.ts`,
`src/services/mock/fixtures.ts`.

**Interfaces (produces):**

- `createMockSheetsApi(tabs: Record<string, Cell[][]>): SheetsApi`. The grid is keyed by tab name,
  row 0 is the header, and the input is deep-copied.
- `MOCK_TABS: Record<string, Cell[][]>` in `fixtures.ts`: `[TabSpec.headers, ...rows]` for
  `ANOMALY_TAB`, `T9MANU_TAB`, `FURNACE_TAB`, `LEVEL_TAB`, `SOLO_RAID_TAB` and the Progression
  audit tab.

- [ ] **Step 1: Failing tests:**
  - Reads: `'T'!A1:C1` gives the header. `'T'!A:A` gives column A down to the last filled row,
    keeping inner blanks as `['']`. `'T'!B3` gives one cell. Values are strings (`5` becomes `'5'`).
    An unknown tab gives `[]`.
  - Writes: `batchUpdateValues` into `'T'!A4:C5` gives back `updatedRanges` equal to the input
    ranges. A later read sees the rows. `"'7.95%"` is stored as `7.95%`, and `12` is read back as
    `'12'`. A write to an unknown tab rejects.
  - Fixtures: every `MOCK_TABS` tab's first row equals its `TabSpec.headers`, and every tab has at
    least 2 data rows.
- [ ] **Step 2:** `yarn vitest run src/services/mock` → FAIL.
- [ ] **Step 3:** Implement. Ranges are parsed with
      `/^'((?:[^']|'')+)'!([A-Z]+)(\d*)(?::([A-Z]+)(\d*))?$/`. A missing row means the whole column.
      Reads drop trailing empty cells and trailing empty rows.
      Fixture dates fall within the last two weeks before 2026-11-19, are fixed (not relative to
      today) and are all in the past.
- [ ] **Step 4:** `yarn vitest run src/services/mock` → PASS.

### Task 2: Mode wiring, banner, docs

**Files:** Create `.env.mock` and `src/config/mock.ts` (`export const MOCK`). Modify
`src/stores/authStore.ts`, `src/main.ts`, `src/App.vue`, `src/vite-env.d.ts` (`VITE_MOCK?:
string`), `package.json` (`"dev:mock": "vite --mode mock"`) and `CLAUDE.md` (a "Reviewing the UI"
section).

**Interfaces:**

- `authStore.ts`: `sheetsApi` becomes a forwarding object. Add `useSheetsApi(api: SheetsApi):
void` to swap the implementation. In mock mode `signedIn` starts `true`, and `signIn` /
  `signOut` only flip the flag.
- `main.ts`: `if (MOCK)` dynamic-imports the mock and the fixtures, calls
  `useSheetsApi(createMockSheetsApi(MOCK_TABS))`, then mounts.

- [ ] **Step 1: Failing test** in a new `src/stores/authStore.test.ts`: after
